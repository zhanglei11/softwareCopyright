# 基础管理模块 PRD

> 所属系统：视觉检测影像质量一致性管控系统
> 文档版本：V1.0 | 创建日期：2026-05-26

---

## 一、模块概述

基础管理模块提供系统的用户账号、角色权限、菜单配置管理能力，采用 RBAC（基于角色的访问控制）模型，支持菜单级与按钮级双层权限控制。

---

| 功能点 | 优先级 | 说明 | 涉及角色 |
|--------|--------|------|----------|
| 用户列表 & 搜索 | P0 | 分页展示，支持多条件筛选 | SUPER_ADMIN |
| 新增 / 编辑用户 | P0 | 填写用户信息并绑定角色 | SUPER_ADMIN |

| 角色授权 | P0 | 为角色分配菜单 & 按钮权限 | SUPER_ADMIN |
| 菜单树管理 | P0 | 树形展示、增删改 | SUPER_ADMIN |

## 三、功能详细说明

### 3.1 用户管理

**功能描述**：系统管理员对平台用户账号进行全生命周期管理。

#### 3.1.1 用户列表

**页面交互说明**：
- 表格列：用户编号、姓名、账号、手机号、部门、角色、状态、创建时间、操作
- 支持按姓名（模糊）、账号（精确）、角色（下拉）、状态（下拉）筛选
- 状态标签：启用（绿色）/ 禁用（灰色）

#### 3.1.2 新增 / 编辑用户

**字段说明**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| 登录账号 | string | ✓ | 6~20 位字母数字，全局唯一 | 创建后不可修改 |
| 姓名 | string | ✓ | 2~20 字 | 显示名称 |
| 手机号 | string | ✓ | 11 位国内手机号格式 | — |
| 部门 | string | ✗ | 最长 50 字 | — |
| 初始密码 | string | ✓（新增） | 8~20 位，须含大小写字母与数字 | 编辑时不显示，单独通过"重置密码"修改 |
| 关联角色 | array | ✓ | 至少选 1 个 | 多选 |

**业务规则**：
- 登录账号全局唯一，重复时提示"账号已存在"
- 禁用用户后，该用户当前 Token 立即失效，下次请求返回 401

#### 3.1.3 操作说明

| 操作 | 前置条件 | 结果 |
|------|----------|------|
| 禁用 | 用户状态为启用 | 状态切换为禁用，Token 失效 |
| 启用 | 用户状态为禁用 | 状态切换为启用 |
| 重置密码 | 任意状态 | 密码重置为 `Abc@12345`，提示管理员告知用户 |
| 删除 | 任意状态 | 逻辑删除（is_deleted=1），操作日志保留 |

---

### 3.2 角色管理

**内置角色（不可删除）**：

| 角色名称 | 标识 | 权限范围 |
|---------|------|---------|
| 超级管理员 | SUPER_ADMIN | 全部权限 |
| 质量标准工程师 | QUALITY_ENG | 质量标准、检测任务全权限 |
| 检测操作员 | OPERATOR | 检测任务执行、结果查看 |
| 管理人员 | MANAGER | 统计看板只读、报表导出 |

**字段说明**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| 角色名称 | string | ✓ | 2~20 字，不可重复 |
| 角色标识 | string | ✓ | 大写字母+下划线，如 QUALITY_ENG，全局唯一 |
| 描述 | string | ✗ | 最长 200 字 |

**业务规则**：
- 仅允许删除无绑定用户的角色
- 删除角色前需确认弹窗提示"确认删除角色 XX？删除后不可恢复"

---

### 3.3 权限管理

采用 RBAC 模型，权限分两层：

| 权限层级 | 说明 | 示例 |
|---------|------|------|
| 菜单权限 | 控制导航菜单可见性 | 质量统计看板菜单 |
| 按钮权限 | 控制操作按钮可见性 | 新增、编辑、删除、导出按钮 |

权限标识规范：`{模块}:{资源}:{操作}`，如 `quality:task:add`

---

### 3.4 菜单管理

**节点类型**：

| 类型 | type 值 | 说明 |
|------|---------|------|
| 目录 | 0 | 一级导航，无路由 |
| 菜单 | 1 | 对应前端路由页面 |
| 按钮 | 2 | 对应页面内操作按钮 |

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 父节点 | bigint | ✗ | 根节点为 null |
| 节点类型 | tinyint | ✓ | 0-目录 / 1-菜单 / 2-按钮 |
| 名称 | string | ✓ | 最长 30 字 |
| 路由地址 | string | ✗ | 菜单节点必填，如 `/quality/tasks` |
| 权限标识 | string | ✗ | 按钮节点必填，如 `quality:task:add` |
| 图标 | string | ✗ | 目录 / 菜单节点使用 |
| 排序 | int | ✓ | 数值越小越靠前 |

**业务规则**：仅可删除无子节点的叶子菜单。

## 四、接口设计

### 4.1 用户管理接口

#### 查询用户列表

```
GET /api/v1/system/users?page=1&pageSize=10&keyword=&roleId=&status=
Authorization: Bearer {token}

Query 参数：
- keyword   string  否  姓名或账号模糊搜索
- roleId    long    否  角色 ID 筛选
- status    int     否  状态筛选：0-禁用 1-启用

响应：
{
  "code": 200,
  "data": {
    "total": 50,
    "page": 1,
    "pageSize": 10,
    "records": [
      {
        "id": 1001,
        "username": "zhangsan",
        "realName": "张三",
        "phone": "13800138000",
        "dept": "质量部",
        "roles": [{"id": 2, "roleName": "质量标准工程师"}],
        "status": 1,
        "createdAt": "2026-05-01 09:00:00"
      }
    ]
  }
}
```

#### 创建用户

```
POST /api/v1/system/users
Authorization: Bearer {token}
Content-Type: application/json

请求体：
{
  "username": "zhangsan",        // 登录账号，6~20位字母数字
  "realName": "张三",            // 姓名
  "phone": "13800138000",        // 手机号
  "dept": "质量部",              // 部门（可选）
  "password": "Abc@12345",       // 初始密码
  "roleIds": [2, 3]              // 关联角色 ID 列表
}

响应：
{ "code": 200, "message": "创建成功", "data": { "id": 1001 } }

错误：
{ "code": 409, "message": "账号已存在：zhangsan" }
```

#### 修改用户

```
PUT /api/v1/system/users/{id}
Authorization: Bearer {token}
Content-Type: application/json

请求体：
{
  "realName": "张三",
  "phone": "13900139000",
  "dept": "检测部",
  "roleIds": [3]
}

响应：{ "code": 200, "message": "修改成功" }
```

#### 修改用户状态

```
PATCH /api/v1/system/users/{id}/status
Authorization: Bearer {token}
Content-Type: application/json

{ "status": 0 }   // 0-禁用 1-启用

响应：{ "code": 200, "message": "状态已更新" }
```

#### 重置密码

```
POST /api/v1/system/users/{id}/reset-password
Authorization: Bearer {token}

响应：{ "code": 200, "message": "密码已重置为初始密码" }
```

#### 删除用户

```
DELETE /api/v1/system/users/{id}
Authorization: Bearer {token}

响应：{ "code": 200, "message": "删除成功" }
```

### 4.2 角色管理接口

#### 查询角色列表

```
GET /api/v1/system/roles?page=1&pageSize=10&keyword=&status=
Authorization: Bearer {token}

响应：
{
  "code": 200,
  "data": {
    "total": 10,
    "page": 1,
    "pageSize": 10,
    "records": [
      {
        "id": 2,
        "roleName": "质量标准工程师",
        "roleCode": "QUALITY_ENG",
        "description": "定义质量标准，配置检测任务",
        "status": 1,
        "userCount": 3
      }
    ]
  }
}
```

#### 创建角色

```
POST /api/v1/system/roles
Authorization: Bearer {token}
Content-Type: application/json

{
  "roleName": "新角色",
  "roleCode": "NEW_ROLE",
  "description": "角色描述"
}

响应：{ "code": 200, "message": "创建成功", "data": { "id": 5 } }
```

#### 角色授权（分配菜单权限）

```
PUT /api/v1/system/roles/{id}/permissions
Authorization: Bearer {token}
Content-Type: application/json

{
  "menuIds": [1, 2, 3, 10, 11, 12]   // 菜单及按钮节点 ID 列表
}

响应：{ "code": 200, "message": "授权成功" }
```

#### 删除角色

```
DELETE /api/v1/system/roles/{id}
Authorization: Bearer {token}

响应：{ "code": 200, "message": "删除成功" }
错误：{ "code": 422, "message": "该角色已绑定 3 个用户，请先解除绑定" }
```

## 六、异常流程

| 异常场景 | 触发条件 | 处理方式 | 用户提示 |
|----------|----------|----------|----------|
| 账号重复 | 新增用户时账号已存在 | 返回 409 | "账号 XX 已存在，请换一个" |
| 角色有绑定用户 | 删除有用户的角色 | 返回 422 | "该角色已绑定 N 个用户，请先解除绑定" |
| 菜单有子节点 | 删除有子节点的菜单 | 返回 422 | "该菜单存在子节点，请先删除子节点" |
| 无权限 | 非 SUPER_ADMIN 访问基础管理接口 | 返回 403 | "无操作权限" |

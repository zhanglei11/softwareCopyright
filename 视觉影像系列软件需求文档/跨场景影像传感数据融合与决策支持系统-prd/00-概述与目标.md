## 一、背景与目标

### 1.1 背景

在复杂工业环境中，质检产线、仓储、物流、安防等多个场景的影像传感数据分散独立，各具不同的采集维度和语义特征，难以形成全局一致的业务认知。

**核心痛点**：
- 多场景数据孤岛：各场景影像数据无统一接入口，无法交叉关联分析
- 决策依赖单点信息：仅凭单一场景数据做决策，易产生误判或漏判
- 融合配置缺乏灵活性：不同业务场景对融合策略的需求差异大，难以统一管控
- 决策过程不可追溯：融合到决策的完整链路缺少记录，问题排查困难

### 1.2 目标

**功能目标**：
- 统一接入多场景影像传感数据源，构建跨场景数据视图
- 支持融合规则与权重的灵活配置，实现数据的多维融合
- 提供决策规则管理，基于融合结果自动触发决策输出
- 展示融合结果与决策结论，支持完整历史追溯
- 集成 RBAC 用户权限管理，实现多角色分级访问控制

**业务目标（上线后）**：
- 跨场景综合判断准确率较单场景提升 ≥ 20%
- 业务决策从人工判断转为系统自动触发，响应时效 ≤ 5 秒
- 管控覆盖面从单场景扩展至全场景

**非目标（本期不涉及）**：
- 影像数据的采集硬件接入与驱动层开发
- AI 算法模型的训练与推理
- 移动端 App 适配

### 1.3 系统定位

- **类型：** PC 端 Web 应用（融合决策前端系统）
- **前端仓库名：** sensor-fusion-decision-support-web
- **后端仓库名：** sensor-fusion-decision-support
- **开发库名：** sensor_fusion_decision_support_dev

### 1.4 运行环境

- **客户端**：PC Web 浏览器（Chrome 90+、Edge 90+）
- **操作系统**：Windows 10 及以上
- **分辨率**：1920×1080 及以上
- **后端技术栈**：Spring Boot 4.x + MySQL 9.x

## 二、用户角色

| 角色 | 标识 | 描述 | 核心诉求 |
|------|------|------|----------|
| 超级管理员 | SUPER_ADMIN | 负责系统配置、用户与权限全量管理 | 快速管控系统全局，掌握用户访问权限 |
| 融合配置工程师 | FUSION_ENG | 配置数据源接入、融合规则、决策规则 | 灵活配置融合策略，快速响应业务变化 |
| 决策分析员 | ANALYST | 查看融合结果、分析决策输出、导出报告 | 快速获取决策依据，支撑业务报告 |
| 只读用户 | READONLY | 查看融合结果与报表，不可修改配置 | 随时了解融合与决策状态 |

**主要用户画像**：
- 姓名：李工
- 职业/场景：工厂质检中心融合配置工程师，日常需要管理多条产线的影像数据融合方案
- 核心需求：在不依赖开发人员的情况下，自主完成数据源接入和融合规则的调整
- 痛点：现有系统每次修改融合策略都要提工单等 IT 支持，响应周期长达 3 天

## 五、全局接口约定

### 5.1 接口前缀规则

| 模块 | 接口前缀 |
|------|---------|
| 用户管理 | `/api/system/users` |
| 角色管理 | `/api/system/roles` |
| 菜单管理 | `/api/system/menus` |
| 权限管理 | `/api/system/permissions` |
| 数据源管理 | `/api/datasource` |
| 融合配置管理 | `/api/fusion/config` |
| 融合方案 | `/api/fusion/schemes` |
| 融合规则 | `/api/fusion/rules` |
| 权重参数 | `/api/fusion/weights` |
| 决策规则管理 | `/api/decision/rules` |
| 决策条件 | `/api/decision/conditions` |
| 融合结果 | `/api/fusion/results` |
| 决策结果 | `/api/decision/results` |
| 报表分析 | `/api/stats` |

### 5.2 统一响应格式

```json
{
  "code": 200,
  "message": "ok",
  "data": { ... }
}
```

分页响应：
```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "total": 100,
    "page": 1,
    "pageSize": 10,
    "records": [ ... ]
  }
}
```

### 5.3 通用错误码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录 / Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突（如数据重复） |
| 422 | 业务规则校验失败 |
| 500 | 服务器内部错误 |

### 5.4 数据库通用字段

所有业务表都包含以下通用字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键（雪花 ID） |
| status | tinyint | 状态：0-停用 1-启用 |
| is_deleted | tinyint | 逻辑删除：0-正常 1-已删除 |
| created_at | datetime | 创建时间（自动填充） |
| created_by | bigint | 创建人 ID |
| updated_at | datetime | 更新时间（自动填充） |
| updated_by | bigint | 更新人 ID |
| remark | varchar(500) | 备注 |

## 六、非功能性需求

| 类别 | 要求 |
|------|------|
| 性能 | 页面加载 ≤ 3 秒；列表查询接口响应 ≤ 3 秒（P99）；融合结果查询 ≤ 3 秒 |
| 安全 | JWT 认证（accessToken 2h + refreshToken 7d）；操作日志全量记录；数据源连接凭证 AES-256 加密存储；接口防重放（X-Request-Id 幂等） |
| 可用性 | 系统可用率 ≥ 99%；配置修改前需用户二次确认；支持配置回滚 |
| 兼容性 | 支持 Chrome 90+、Edge 90+ |
| 数据保留 | 融合结果与决策记录保留 2 年；操作日志保留 1 年 |
| 并发 | 支持 50 个并发用户；核心查询接口支持 200 QPS |
